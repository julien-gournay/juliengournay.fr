🎵 Concertothèque

Gestionnaire personnel de concerts — Flutter + Firebase

v1.0.0+1 Flutter 3.x / Dart 3 Firebase Windows · macOS · Android · iOS

📌 Aperçu du projet

Concertothèque est une application de bureau (Windows, prioritaire) et mobile (Android / iOS) développée avec Flutter. Elle permet à un utilisateur de tenir un journal personnel de tous les concerts qu'il a assistés ou prévoit d'assister, en gérant les artistes, les salles et les statistiques associées.

Les données sont synchronisées en temps réel via Cloud Firestore et l'authentification est assurée par Firebase Auth. Des notifications locales rappellent les concerts à venir (J-7 et J-1).

✨ Fonctionnalités

Gestion des concerts

  • Création / édition / suppression avec confirmation
  • Types d'événement : Concert, Festival, Soirée, Showcase, Comédie musicale
  • Placements : Fosse, Gradin, Catégorie 1–4, Carré Or
  • Liaison à une salle (avec création inline) et à des artistes (multi-sélection)
  • Images : affiche et couverture par URL
  • Archivage automatique lorsque la date est passée
  • Filtres avancés (nom, ville, artiste, type) + tri multi-colonnes
  • Sélection multiple pour suppression groupée

Gestion des artistes & lieux

  • CRUD complet avec pagination (25 éléments / page)
  • Recherche instantanée par nom / genre
  • Page de détail avec liste des concerts associés

Dashboard & statistiques

  • Nombre total de concerts, à venir, archivés
  • Total des dépenses (billets + dépenses supplémentaires)
  • Top 5 artistes les plus vus (barres de progression)
  • Top 5 salles les plus visitées
  • Prochains concerts à venir

Notifications

  • Rappels automatiques J-7 et J-1 au démarrage de l'app
  • Notifications depuis Firestore Inbox (Firebase Console / Cloud Functions)
  • Windows : Toast natif via flutter_local_notifications
  • Mobile : FCM + flutter_local_notifications
  • Anti-doublon via SharedPreferences

Fonctionnalités Windows spécifiques

  • Icône dans la barre des tâches (system tray) avec menu contextuel
  • Option "Minimiser dans le systray" au lieu de fermer
  • Démarrage automatique au lancement de Windows (registre HKCU\…\Run)

Paramètres & compte

  • Sélecteur de thème : Système / Clair / Sombre
  • Modification du profil (nom d'affichage)
  • Suppression de compte avec ré-authentification
  • Export CSV séparé pour chaque collection
  • Journalisation des erreurs (Crashlytics mobile, Firestore desktop)

⚙️ Services

Services de données Firestore

Les trois services (EvenementService, ArtisteService, LieuService) suivent le même patron :

  • Collection : users/{uid}/{evenements|artistes|lieux}
  • Pagination curseur : 25 éléments par page
MéthodeRetourDescription
fetchPage({cursor})Future<List>Page paginée (cursor-based)
fetchAll()Future<List>Jeu complet (pour export)
stream()Stream<List>Temps réel (artistes, lieux)
add(item)Future<void>Créer un document
update(item)Future<void>Modifier un document
delete(id)Future<void>Supprimer un document

NotificationService

Gère les notifications locales et push selon la plateforme :

MéthodeDescription
initialize()Init platform-specific (Toast ou FCM)
canShow()Vérifie paramètres app + permission OS
show(title, body, id)Affiche une notification
isOsPermissionGranted()Vérifie permission OS
getToken()Token FCM (mobile uniquement)

ReminderService

Au démarrage de l'app, interroge Firestore pour les concerts dans les 7 prochains jours :

  • Rappel à J-7 (clé SharedPreferences : {id}_j7)
  • Rappel à J-1 (clé SharedPreferences : {id}_j1)
  • Anti-doublon : les rappels déjà envoyés ne sont plus réémis

InboxService

Écoute la collection users/{uid}/inbox en temps réel :

  • Déclenchement sur tout document avec read: false
  • Marque automatiquement le document read: true après affichage
  • Cycle de vie géré manuellement : start() / stop() (login/logout)

ExportService

  • Exports CSV avec BOM UTF-8 (compatibilité Excel)
  • Dialogue natif "Enregistrer sous" via file_picker
  • Séparateur : virgule, valeurs entre guillemets si nécessaire
  • Format date : ISO 8601 (YYYY-MM-DD)

TrayService Windows

  • Singleton implémentant TrayListener et WindowListener
  • Menu contextuel : "Ouvrir Concertothèque" / "Quitter"
  • Intercepte la fermeture si minimizeToTray est activé
  • Icône : windows/runner/resources/concertotheque.ico

AutostartService Windows

  • Registre : HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  • Commande reg add / reg delete via Process.run
  • Méthodes : isEnabled(), setEnabled(bool)

CrashLogger

  • Mobile : délègue à Firebase Crashlytics
  • Desktop : écrit dans users/{uid}/crash_logs (Firestore)
  • Champs : error, stack, platform, fatal, timestamp
  • Intégré dans runZonedGuarded (erreurs async non gérées)

Règles Firestore recommandées

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
  }
}

🗄️ Structure Firestore

users/
  {uid}/
    evenements/ ← concerts
      {docId}
        nomEvent string
        date timestamp
        typeCode string
        placement string
        prixBillet number
        depenseSup number

      {docId}
        nom, genre, photo string

    lieux/
      {docId}
        nom, ville, pays, adresse, type string
        capacite number
        photo, siteWeb string

    inbox/ ← messages push

        title, body string
        read boolean

    crash_logs/ ← desktop uniquement
      {docId}
        error, stack, platform, fatal, timestamp
Toutes les collections sont scoped sous users/{uid}/ — un utilisateur ne peut accéder qu'à ses propres données grâce aux règles Firestore.

🔔 Système de notifications

Architecture

Trois canaux de notification coexistent :

  1. Rappels automatiques (ReminderService)
    Au démarrage, interroge Firestore pour les concerts dans les 7 prochains jours. Envoie une notification J-7 et J-1. Résistant aux redémarrages grâce à SharedPreferences ({id}_j7 / {id}_j1).
  2. Inbox Firestore (InboxService)
    Listener temps réel sur users/{uid}/inbox. Tout document read: false déclenche une notification et est marqué read: true. Utile pour les campagnes depuis Firebase Console ou Cloud Functions.
  3. Push mobile (FCM)
    Firebase Cloud Messaging reçoit les messages push en arrière-plan sur Android/iOS. Le token FCM est récupérable via NotificationService.getToken().

Par plateforme

PlateformeImplémentation
Windowsflutter_local_notifications → Toast natif Windows
AndroidFCM + flutter_local_notifications (canal "concerts")

🏗️ Compilation

Prérequis

  • Flutter SDK ≥ 3.x (flutter --version)
  • Dart ≥ 3.0
  • FlutterFire CLI (dart pub global activate flutterfire_cli)
  • Pour Windows : Visual Studio 2022 + workload "Desktop development with C++"
  • Pour Android : Android Studio + NDK
  • Inno Setup 6 (optionnel, pour l'installeur .exe)

Commandes

# Installer les dépendances
flutter pub get

# Lancer en développement
flutter run -d windows
flutter run -d android

# Build release Windows
flutter build windows --release

# Build release Android (APK)
flutter build apk --release

# Build release Android (Bundle)
flutter build appbundle --release

# Regénérer les options Firebase
flutterfire configure

Installeur Windows (Inno Setup)

Après flutter build windows --release, l'exécutable se trouve dans build/windows/x64/runner/Release/. Inno Setup crée un installeur .exe avec raccourci bureau et désinstalleur.

Le projet est distribué via Scoop (gestionnaire de paquets Windows). Le manifest Scoop pointe vers l'archive ZIP du release GitHub.
